## Key Decisions

### 1. Global, never-reused dependency number
A dependency spans two projects, so a per-project number would give it two different names; the number is one past the max seen across live rows and the version trail, matching legacy's `dependency_numbers` sequence.

### 2. Status is derived, never set
NEW/ACCEPTED/RESOLVED are recomputed from resolving-card links and the sticky RESOLVED toggle rather than stored as an independent field a caller could desync — a toggle on a NEW dependency with no linked cards is a no-op.

### 3. History gets a fourth trail rather than a separate feed
`dependency_versions` joins the existing union query (project/card/page/murmur trails) matched on either project id, so dependencies show up in both projects' history and Atom feeds without a parallel notification path — consistent with the ADR-0004/ADR-0016 union-trail pattern already established for the other three trails.
