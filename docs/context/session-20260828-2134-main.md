### Flaky test fix (caught by the new gate's first run)
- `mingle-ts/test/auth-configuration.behavior.test.ts` — the sealer tamper-detection test did `a.open(sealed.slice(0, -2) + "zz")` on the base64url-encoded sealed value. The trailing base64url character carries padding bits, so roughly 1 in 256 sealed values already end in a character whose meaningful bits are unchanged by substituting `zz` — the "tamper" decoded to identical ciphertext bytes and AES-256-GCM correctly accepted it, producing an intermittent false failure. Fixed by decoding the ciphertext segment, flipping byte 0 (`^= 0xff`), and re-encoding before asserting `open` throws — a tamper that is guaranteed to change the decoded bytes every run.
- `app/domain/identity/sealer.server.ts` (the sealer itself) was **not** changed — it was never at fault. No production source code changed this session.
