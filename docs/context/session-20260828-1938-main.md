## Key Decisions

### 1. API credentials are distinct from the session, and secrets are sealed at rest (ADR-0020)
Bearer API keys and HMAC signing secrets never touch the session cookie; the bind password, OIDC client secret, and signing secrets are encrypted at rest (AES-256-GCM) rather than stored plaintext. ACCEPTED, no Open Questions. `docs/adrs/0020-api-credentials-are-distinct-from-the-session-and-secrets-are-sealed-at-rest.md`.

### 2. Wire-crossing constants belong in `wire-types.ts`, not `.server` modules (rule 8b)
The build break was the second occurrence of the exact same defect class (see Recurrence Check) — a value needed by both a browser route component and a server module lived in a `.server.ts` file. Same fix applied: extract to the shared wire-types file.

### 3. External sign-in never grants admin, and auto-enrolled accounts get an unusable password hash
Matches (and deliberately narrows) legacy behavior — legacy's `auto_enroll_as_mingle_admin` config option was dropped rather than ported, closing a privilege-escalation surface via SSO auto-enrollment.

### 4. LDAP-enabled deployments keep password auth for site admins only
A stated departure from a pure LDAP-only strategy list, kept as a lock-out safeguard if the directory becomes unreachable.
