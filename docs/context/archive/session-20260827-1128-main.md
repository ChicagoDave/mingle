## Key Decisions

### 1. Axis ordering is a query concern, not a presentation concern (ADR-0016)
The axis is a `SELECT DISTINCT <x property>` executed with an `orderBy` on the grouping column, so the evaluator's `orderExpr` decides — enumerated properties return in DEFINED POSITION with the unset bucket leading, byte-for-byte the order `card-grid.behavior.test.ts:204` already asserts for an enumerated lane. A JS sort would put `10` before `9` and `Closed` before `Open`, and would let a chart and a card grid disagree about the same cards.

### 2. Two defects found in this session's own new code, neither caught by the first green suite
(a) An undeclared `combine` was treated as overlay-bottom and therefore subtracted from a `total` series, shrinking the total bar by a series the author never declared it contained (legacy's `normal_series` stack but are not subtracted). (b) The first suite asserted only on `<desc>` values, so mutants that stopped bars stacking and that scaled the y axis to the tallest series instead of the tallest column both survived — geometry assertions were added to close it. Also removed a guard added earlier for an empty `series:` list after confirming `parseSequence` cannot return `[]` — dead code, not a fix.

### 3. ADR-0016 written and ACCEPTED
`docs/adrs/0016-categorical-ordering-is-a-query-concern.md` — 5 decisions, 6 consequences, no open questions. `adr-review` scored 17/17 after one fix. The review's single finding was a false ADR-0006 attribution (claimed ADR-0006 settled that ordering is part of the resolved parse; it settles the resolved *typed AST*, not this). **This is the third time this corpus has caught an ADR-0006 overclaim**: the Phase 17 review caught one, ADR-0014's closing note warned about it explicitly ("extends ADR-0006's principle one layer down; it is not something ADR-0006 already decided"), ADR-0015 quoted that warning, and it was made again anyway this session.
