### Two real defects found and fixed (both produce right-looking wrong answers)
1. Drizzle qualifies columns inside a `sql` template in WHERE position but NOT in SELECT position. The evaluator's correlated `valueExpr` subquery therefore rendered `where "card_id" = "id"` in a select list, and SQLite resolved that bare `"id"` against the SUBQUERY's own table — a legal query silently returning another row's value. Surfaced as a pie chart where every group was labelled "open" while counts were correct. Fixed by emitting table-qualified references via `getTableName`. Verified load-bearing: applying the unqualified mutant failed 9 tests; reverted. Nuance: Phase 13's shipped filter path was never wrong — all its uses land in WHERE position, and `inQuery` builds one template embedded in WHERE position too. The defect was that the expression was position-*dependent*, which is what made reuse across positions unsafe.
2. `GROUP BY <ordinal>` is an ORDER-BY-only feature in SQLite; an integer literal in GROUP BY is a constant, collapsing every row into one group while still returning a plausible count. The first fix attempt used it and was wrong; reverted to the expression form, which now works identically in both positions per fix #1.

## Key Decisions

### 1. Hand-written YAML-subset parser instead of a YAML dependency
Legacy's own `Macro.parse_parameters` has to explicitly refuse `!ruby/` tags (verified at `mingle/lib/macro/macro.rb:91`) — a full YAML parser is unnecessary attack surface for a parameter grammar this narrow.

### 2. Table-qualified SQL references in `valueExpr`
Drizzle's positional column-qualification behavior (qualifies in WHERE, not SELECT) made the previously-shipped correlated subquery expression silently position-dependent. Qualifying explicitly via `getTableName` removes the dependency rather than papering over the one call site that broke.

### 3. Declared allowlist extension point over widening the allowlist in place
ADR-0014: `registerMacroElements` lets macro output opt into elements (`<svg>`) that authored content still cannot produce, keeping the two trust boundaries (author-written vs. macro-generated) distinct and independently testable.

### 4. Refusals render in place, not silently
A macro that can't resolve renders `<div class="error macro">` inline rather than disappearing — matches legacy intent and avoids a page silently losing content.

### 5. Commit, don't delete, the two orphaned event logs
15 of 17 archived logs were already tracked; treating the two orphans as accidentally-unstaged (not intentionally-untracked) restores the established convention. This corrected the user's originally approved housekeeping plan and was flagged as a correction rather than applied silently.
