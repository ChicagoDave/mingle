## Key Decisions

### 1. ADR-0005 — Favorites as one row with a `kind` discriminator
Collapses legacy `Favorite` + `CardListView` into a single `favorites` row (legacy wire-form params, case-insensitive partial-unique-index name scoping) so Phase 16 page favorites extend the row with `kind`/`page_id` rather than a second table or a polymorphic join SQLite can't enforce.

### 2. ADR-0006 — MQL parses to a resolved, typed AST
The parser hands every consumer (filters now, chart macros and history charts later) a `PropertyRef`+canonical-literal AST rather than a name-keyed syntax tree, so evaluators never re-resolve names or re-validate literals; unsupported legacy constructs (trees, tags, plans) parse but are rejected by the resolver with a specific message, keeping the grammar and AST stable as those models arrive later.

### 3. Bare date literals accepted (deviation from `card_query.grammar`)
Phase 12's lexer follows legacy `mql.grammar`'s more permissive date-literal rule rather than `card_query.grammar`'s, a deliberate divergence noted in both the plan and ADR-0006 rather than a silent gap.
