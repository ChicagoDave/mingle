## Key Decisions

### 1. Content sanitization is parse-and-rebuild, not passthrough (ADR-0011)
Output is always generated from a parsed representation, never the raw input passed through with modifications, so unknown markup structurally cannot survive. This binds Phase 17's macro framework to produce nodes before serialization, not string-splice into rendered HTML.

### 2. Page names are references; renames are all-or-nothing (ADR-0012)
A name stored inside human-authored text that is later resolved by name — a page name in `[[…]]`, a property name in a formula, in stored MQL, or in an encoded filter — is a reference, not incidental text. Renaming the referent must rewrite every occurrence in one transaction (appending a version to each versioned aggregate it touches) or be refused; page rename is currently refused, matching legacy. The rule generalizes the property-rename open item that had been carried unshaped since Phase 11. It narrows ADR-0004's "a rename updates only `property_definitions.name`" to its actual subject — history, where rename must never rewrite snapshots — rather than exempting properties from the rule.

### 3. Interim textarea editor with a documented mount seam, not a blocked session
When npm's registry was unreachable, the phase proceeded with a plain textarea (real save path, real persistence) instead of stalling on the dependency install, then swapped in TipTap once the registry recovered without touching the persistence layer.
